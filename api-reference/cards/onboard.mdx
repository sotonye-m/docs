---
title: "Onboard Card Customer"
api: "POST /v1/yativo-card/customers/onboard"
description: "Initialize card onboarding for an issuer-program customer"
authMethod: "bearer"
---

<ParamField header="Authorization" type="string" required>
  Bearer token: `Bearer YOUR_ACCESS_TOKEN`
</ParamField>

<ParamField body="email" type="string" required>
  Customer email address used for card onboarding and OTP delivery.
</ParamField>

<ParamField body="external_customer_id" type="string">
  Optional partner-side reference for this customer (your own ID or key). Stored and
  returned as-is so you can correlate records on your side.
</ParamField>

<Note>
  Only `email` is required. Pass `external_customer_id` to attach your own reference to
  the record. `customer_id` is generated by Yativo and returned in the response — do not
  send it in the request.
</Note>

<RequestExample>
```bash
curl -X POST 'https://crypto-api.yativo.com/api/v1/yativo-card/customers/onboard' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "email": "user@example.com",
    "external_customer_id": "merchant_user_8821"
  }'
```
</RequestExample>

<ResponseExample>
```json
{
  "success": true,
  "message": "Customer card onboarding initiated. Verification code sent to customer email.",
  "data": {
    "yativo_card_id": "yativo_card_customer_8f9a..._1769031332068",
    "customer_id": "6627f3a2c5d4e100123abcde",
    "external_customer_id": "merchant_user_8821",
    "email_masked": "us***@example.com",
    "next_step": "verify_otp",
    "otp_expires_in_seconds": 600
  }
}
```
</ResponseExample>

## Next Steps In API Reference

1. Verify OTP: `POST /v1/yativo-card/customers/{yativoCardId}/verify-otp`
1. Retrieve KYC link: `GET /v1/yativo-card/customers/{yativoCardId}/kyc-link`
1. Check KYC status: `GET /v1/yativo-card/customers/{yativoCardId}/kyc-status`
1. Create virtual card: `POST /v1/yativo-card/customers/{yativoCardId}/cards/virtual`

<Note>
  Card wallet provisioning is handled automatically by Yativo after KYC approval — no manual
  deploy step is required. When KYC status first returns `approved`, the wallet is provisioned
  in the background and the card will be ready for virtual card creation within ~1 minute.
</Note>
