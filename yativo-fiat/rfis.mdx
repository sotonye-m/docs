---
title: "Compliance RFIs (requests for information)"
description: "List compliance RFIs and reply with answers"
---

When a payment partner needs more information about a customer, payment, or transfer, Yativo records an **RFI** (request for information) on your account. You can list RFIs and reply from your own UI or workflow.

<Warning>
  Answers you save or submit through the API are **reviewed by Yativo** before anything is sent upstream. Yativo operations submits approved responses from the internal RFI workspace.
</Warning>

API responses do not include upstream partner names, external reference ids, or third-party dashboard links.

## Environments

| Environment | Base URL |
|---|---|
| Production | `https://api.yativo.com/api/v1` |
| Sandbox | `https://smtp.yativo.com/api/v1` |

Authenticate with `X-Api-Key` and `X-Api-Secret`. Team members need `team.kyc.view` to read RFIs and `team.kyc.submit` to reply.

## Webhooks

When an RFI is created or its state changes, Yativo posts to your webhook URL:

- `rfi.created` — new RFI
- `rfi.updated` — status change
- `rfi.response_required` — open and waiting on you

See [RFI webhook payloads](/yativo-fiat/webhooks#rfi-events-rficreated-rfiupdated-rfiresponse_required).

## List RFIs

```
GET /business/rfis
```

Query: `open_only=1`, `response_required=1`

<RequestExample>
```bash cURL
curl -G 'https://api.yativo.com/api/v1/business/rfis' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  --data-urlencode 'open_only=1'
```
</RequestExample>

| Value | Meaning |

## Show RFI

```
GET /business/rfis/{id}
```

`id` is Yativo's internal RFI id (same as `payload.id` in webhooks). Returns one object with the same shape as a list row.

## Reply to RFI

```
PUT /business/rfis/{id}/draft-responses
```

<RequestExample>
```bash cURL
curl -X PUT 'https://api.yativo.com/api/v1/business/rfis/42/draft-responses' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: rfi-reply-001' \
  -d '{
    "responses": {
      "2095d3da-2761-4d30-93e6-b46018bf576a": {
        "text": "E-commerce reseller",
        "free_text_explanation": "I sell consumer electronics on eBay to retail buyers.",
        "document_list": [
          {
            "file": "data:application/pdf;base64,JVBERi0xLjQK…",
            "description": "Bank statement"
          }
        ]
      }
    }
  }'
```
</RequestExample>

Keys must match `requested_items[].id`. Each item accepts only the field names listed in that item's `response_types`.

| `response_types` | JSON field | Shape |
|---|---|---|
| `text` | `text` | string |
| `free_text_explanation` | `free_text_explanation` | string |
| `date` | `date` | ISO date string |
| `boolean` | `boolean` | boolean |
| `text_list` | `text_list` | string array |
| `address` | `address` | object (`street_line_1`, `country`, …) |
| `document_list` | `document_list` | array of `{ "file": "data:…;base64,…", "description": "…" }` on write (PDF/images only, max 24 MB per file); reads return `file_attached: true` instead of base64 |
| `identifying_information_list` | `identifying_information_list` | array of ID objects |

Partial replies merge with answers already on file; omitting `document_list` keeps previously uploaded documents.

The response matches **Show RFI** with `draft_responses` populated and `draft_responses_at` set. Document bytes are not echoed on GET — only `file_attached` and `description`.

To require every `requested_items[]` entry in one call, use `POST /business/rfis/{id}/responses` with the same JSON body. That endpoint returns `422` if any item is missing or incomplete.
