---
title: "Webhooks"
description: "Receive real-time event notifications for payments, transfers, cards and account activity"
---

Webhooks push an event to your server when something happens on your account, such as a deposit landing, a payout settling or a card being charged. You register one HTTPS URL, and every event is sent to it.

| | |
|---|---|
| HTTP method | `POST` |
| Content type | `application/json` |
| Signature header | `Signature` |
| Signature algorithm | HMAC-SHA256, hex-encoded |
| Timeout | 3 seconds |
| Success | Any `2xx` status |

<Warning>
  The signature header is named `Signature`. It is not `X-Yativo-Signature` or `X-Signature`. Always [verify it](#verify-the-signature) before you process an event.
</Warning>

---

## Register your endpoint

### Create or replace your webhook

```
POST https://api.yativo.com/api/v1/business/webhook
```

<ParamField body="url" type="string" required>
  The HTTPS endpoint that receives events.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST 'https://api.yativo.com/api/v1/business/webhook' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: webhook-setup-001' \
  -d '{ "url": "https://your-app.com/webhooks/yativo" }'
```
</RequestExample>

<ResponseExample>
```json Success
{
  "status": "success",
  "status_code": 200,
  "message": "Request successful",
  "data": {
    "id": "b1a7c6e0-4b2a-4c39-9c2e-3a2f6a8e9d10",
    "user_id": 1024,
    "url": "https://your-app.com/webhooks/yativo",
    "secret": "aZ3kP9mQw2Ry7Ln5Xj1Vb8Ct4Fh6Ds0G",
    "events": "general",
    "created_at": "2026-09-07T14:32:10.000000Z",
    "updated_at": "2026-09-07T14:32:10.000000Z"
  }
}
```
</ResponseExample>

- **One endpoint per account.** Calling `POST /business/webhook` again replaces your URL and issues a new secret.
- Save the `secret`. You need it to verify signatures.
- Every event goes to your URL. There's no per-event subscription, so ignore event types you don't handle.
- Right after you save a webhook, Yativo sends a [`webhook_updated`](#account-and-platform-events) test event to the new URL.

### Other webhook endpoints

| Endpoint | Description |
|---|---|
| `GET /business/webhook` | Your webhook, inside a `data` array |
| `PUT /business/webhook/{webhook_id}` | Change the URL. The secret stays the same |
| `POST /business/webhook/{webhook_id}/regenerate-secret` | Issue a new secret. The old one stops working immediately |
| `DELETE /business/webhook/{webhook_id}` | Delete your webhook |

## Verify the signature

Every request carries a `Signature` header:

```
Signature: hex( HMAC_SHA256( raw_request_body, your_webhook_secret ) )
```

Compute the HMAC over the exact raw request body. Don't parse and re-serialize the JSON first, because whitespace or key order changes break the match. Compare with a constant-time function.

Requests also carry a `Timestamp` header (Unix seconds). It isn't part of the signature.

<CodeGroup>

```javascript Node.js
const crypto = require('crypto');

app.post('/webhooks/yativo', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.header('Signature') || '';
  const expected = crypto
    .createHmac('sha256', process.env.YATIVO_WEBHOOK_SECRET)
    .update(req.body) // raw Buffer, not the parsed object
    .digest('hex');

  const valid =
    signature.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));

  if (!valid) return res.status(401).send('Invalid signature');

  const event = JSON.parse(req.body);
  res.sendStatus(200);
  // process the event after responding
});
```

```python Python
import hmac, hashlib, os
from flask import Flask, request, abort

app = Flask(__name__)

@app.route('/webhooks/yativo', methods=['POST'])
def webhook():
    raw_body = request.get_data()
    signature = request.headers.get('Signature', '')

    expected = hmac.new(
        os.environ['YATIVO_WEBHOOK_SECRET'].encode(), raw_body, hashlib.sha256
    ).hexdigest()

    if not hmac.compare_digest(expected, signature):
        abort(401)

    event = request.get_json()
    return '', 200
```

```php PHP
<?php
$payload = file_get_contents('php://input'); // raw body
$signature = $_SERVER['HTTP_SIGNATURE'] ?? '';

$expected = hash_hmac('sha256', $payload, getenv('YATIVO_WEBHOOK_SECRET'));

if (!hash_equals($expected, $signature)) {
    http_response_code(401);
    exit('Invalid signature');
}

$event = json_decode($payload, true);
```

```go Go
func webhookHandler(w http.ResponseWriter, r *http.Request) {
    body, _ := io.ReadAll(r.Body)

    mac := hmac.New(sha256.New, []byte(os.Getenv("YATIVO_WEBHOOK_SECRET")))
    mac.Write(body)
    expected := hex.EncodeToString(mac.Sum(nil))

    if !hmac.Equal([]byte(expected), []byte(r.Header.Get("Signature"))) {
        http.Error(w, "Invalid signature", http.StatusUnauthorized)
        return
    }

    w.WriteHeader(http.StatusOK)
}
```

```java Java
@PostMapping("/webhooks/yativo")
public ResponseEntity<String> webhook(
    @RequestHeader("Signature") String signature,
    @RequestBody byte[] rawBody
) throws Exception {
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(System.getenv("YATIVO_WEBHOOK_SECRET").getBytes(), "HmacSHA256"));

    StringBuilder hex = new StringBuilder();
    for (byte b : mac.doFinal(rawBody)) hex.append(String.format("%02x", b));

    if (!MessageDigest.isEqual(hex.toString().getBytes(), signature.getBytes())) {
        return ResponseEntity.status(401).body("Invalid signature");
    }
    return ResponseEntity.ok("OK");
}
```

```ruby Ruby
post '/webhooks/yativo' do
  payload = request.body.read
  expected = OpenSSL::HMAC.hexdigest('SHA256', ENV['YATIVO_WEBHOOK_SECRET'], payload)

  halt 401, 'Invalid signature' unless Rack::Utils.secure_compare(expected, request.env['HTTP_SIGNATURE'].to_s)

  event = JSON.parse(payload)
  status 200
end
```

```csharp C# (.NET)
[HttpPost("/webhooks/yativo")]
public async Task<IActionResult> Webhook()
{
    using var reader = new StreamReader(Request.Body);
    var rawBody = await reader.ReadToEndAsync();

    using var hmac = new HMACSHA256(Encoding.UTF8.GetBytes(Environment.GetEnvironmentVariable("YATIVO_WEBHOOK_SECRET")));
    var expected = Convert.ToHexString(hmac.ComputeHash(Encoding.UTF8.GetBytes(rawBody))).ToLowerInvariant();

    if (!CryptographicOperations.FixedTimeEquals(
        Encoding.UTF8.GetBytes(expected),
        Encoding.UTF8.GetBytes(Request.Headers["Signature"].ToString())))
        return Unauthorized("Invalid signature");

    return Ok();
}
```

</CodeGroup>

The signed body has no timestamp, so pair signature checks with [deduplication](#best-practices).

## Payload envelope

Every event uses this envelope:

```json
{
  "event.type": "deposit.updated",
  "payload": { }
}
```

`event.type` names the event. `payload` holds the event data. The envelope has no delivery ID or timestamp, so use fields inside `payload`, such as `id`, `event_id`, `status` and `created_at`, to deduplicate and order events.

### The customer object

Every payload includes `customer_id` and a `customer` object, so you know whose event it is without another API call:

```json
"customer": {
  "customer_id": "b8d1c6b0-2f3a-4b8e-9d1a-3c5f6e7a8b90",
  "customer_email": "jane@example.com",
  "customer_name": "Jane Doe",
  "customer_phone": "+15551234567",
  "customer_type": "individual"
}
```

`customer_type` is `individual` or `business`. `customer` is `null` when the event isn't about one of your customers, for example `user.updated`. Only these five fields are sent.

## Event catalog

| Event | Sent when |
|---|---|
| `deposit.created`, `deposit.updated` | A deposit is created, or its status changes |
| `payout.updated` | A payout changes status |
| `customer.created`, `customer.updated` | A customer is created, or their profile or KYC status changes |
| `endorsement.updated` | A customer's endorsement status changes. This is how you learn KYC and KYB results |
| `virtual_account.created`, `virtual_account.updated` | A virtual account is provisioned or updated |
| `virtual_account.deleted` | You delete a virtual account |
| `virtual_account.deposit` | Funds land in a virtual account |
| `metadata.created`, `metadata.updated` | Metadata is attached to, or changed on, a transaction |
| `tracking.created` | A tracking update is posted on a transaction |
| `crypto.wallet.created` | A stablecoin deposit address is created |
| `crypto.deposit.completed` | A stablecoin deposit lands |
| `crypto_deposit` | Older name for a completed stablecoin deposit, still sent by some flows |
| `wallet.deleted` | A stablecoin deposit address is deleted |
| `virtualcard.*` | Virtual card KYC, lifecycle, funding, transactions and declines |
| `business_spend_card.*` | Corporate card issuance, funding, transactions, disputes and status changes |
| `user.updated` | Your account name, email, membership ID or KYC status changes |
| `webhook_updated` | You create or replace your webhook |
| `payin_method.enabled`, `payin_method.disabled` | A payin method is turned on or off for everyone |
| `payout_method.enabled`, `payout_method.disabled` | A payout method is turned on or off for everyone |

New event types are added over time. Ignore ones you don't recognize.

## Virtual cards

Every `virtualcard.*` payload includes:

- `event_id`: unique per event, and the same on every redelivery. Use it to deduplicate
- `card_id`: the card ID you pass to the card endpoints
- `customer_id` and `customer`: the cardholder

Amounts are decimal USD (`4.5` means $4.50).

### KYC

| Event | Sent when |
|---|---|
| `virtualcard.user.kyc.pending` | Verification was received and is under review. Not a final result |
| `virtualcard.user.kyc.complete` | Verification passed. You can now create a card for this customer |
| `virtualcard.user.kyc.failed` | Verification was rejected. Resubmit after the customer fixes what `rejection_details` describes |

```json
{
  "event.type": "virtualcard.user.kyc.failed",
  "payload": {
    "event_id": "6f1c2a9e-4b7d-5e8f-9a0b-1c2d3e4f5a6b",
    "customer_id": "b8d1c6b0-2f3a-4b8e-9d1a-3c5f6e7a8b90",
    "kyc_status": "rejected",
    "reason": "RETRY: UNSATISFACTORY_PHOTOS",
    "rejection_details": [
      {
        "code": "UNSATISFACTORY_PHOTOS",
        "message": "The document or its details could not be read clearly. Please upload a sharper photo."
      }
    ],
    "customer": { "customer_id": "b8d1c6b0-2f3a-4b8e-9d1a-3c5f6e7a8b90", "...": "..." }
  }
}
```

`kyc_status` is `under_review`, `approved` or `rejected`. Show `rejection_details[].message` to your customer and branch on `code`.

### Card lifecycle

| Event | Sent when | Effect on your USD wallet |
|---|---|---|
| `virtualcard.created.completed` | The card is issued and ready to use | None |
| `virtualcard.created.failed` | Issuing failed after the request was accepted | Creation fee, top-up fee and opening balance are refunded |
| `virtualcard.regularized` | A card recovered from an indeterminate state. `status` is its new status | None |
| `virtualcard.expiration` | The card reached its expiry date. Includes `expired_at` | None |
| `virtualcard.contactless.activation` | Contactless payments were turned on. Includes `activated_at` | None |
| `virtualcard.terminated.refund` | The card was terminated and its balance returned | `amount` is credited |
| `virtualcard.transaction.terminated.refund` | A refund was posted while terminating the card | Credited once per card across both termination events |
| `virtualcard.deactivated` | The card was frozen after 2 failed charge attempts | None |

When you terminate a card through the API, the remaining balance reaches your wallet when `virtualcard.terminated.refund` arrives, not in the terminate response.

### Funding

| Event | Sent when | Effect on your USD wallet |
|---|---|---|
| `virtualcard.topup.completed` | A top-up reached the card | None. Your wallet was debited when you requested it |
| `virtualcard.topup.failed` | A top-up failed after it was accepted | Top-up amount and fee are refunded |
| `virtualcard.withdrawal.completed` | A withdrawal from the card completed | None. Your wallet was credited when you requested it |
| `virtualcard.withdrawal.failed` | A withdrawal failed after it was accepted | The wallet credit is reversed |

## Respond to a webhook

- Return a `2xx` status as soon as you've stored or queued the event. Do slow work afterwards.
- Respond within **3 seconds**. Some events are sent while the API call that caused them is still running, so a slow endpoint can slow that call down.
- Yativo doesn't read your response body. An empty `200` is enough.
- A non-`2xx` status, a connection error or a timeout is a failed delivery. Failed deliveries are retried up to 3 times in total, with exponential backoff, then dropped. [Resend](#resend-an-event) any event you missed.

```javascript Node.js
app.post('/webhooks/yativo', express.raw({ type: 'application/json' }), async (req, res) => {
  if (!verifySignature(req)) return res.status(401).end();

  const event = JSON.parse(req.body);
  res.sendStatus(200); // acknowledge first

  const type = event['event.type'];
  const payload = event.payload;

  switch (type) {
    case 'deposit.updated':
      if (payload.status === 'success') await creditOrder(payload.id, payload.receive_amount);
      break;
    case 'payout.updated':
      await updatePayout(payload.id, payload.status);
      break;
    case 'virtual_account.deposit':
      await notifyCustomer(payload.customer_id, payload.amount);
      break;
    default:
      // ignore events you don't handle
  }
});
```

### Resend an event

```
POST https://api.yativo.com/api/v1/business/events/resend/{eventId}
```

`eventId` is the `id` from the delivery log, not an ID from inside the event's payload.

```bash
curl -X POST 'https://api.yativo.com/api/v1/business/events/resend/981' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Idempotency-Key: resend-981'
```

```json
{
  "status": "success",
  "status_code": 200,
  "message": "Request successful",
  "data": { "message": "Webhook event resend has been queued" }
}
```

- The original payload is resent, signed with your current secret, to the URL you have registered now. Fields that events no longer carry are left out.
- The resend appears as a new entry in the delivery log.
- `404 Webhook event not found` means the ID isn't in your log. `400 No webhook endpoint is configured for your account` means you have no webhook.

## Best practices

- **Verify every signature** before trusting the contents.
- **Respond fast, process later.** Return `2xx` immediately and do the work in a background job.
- **Deduplicate.** The same event can arrive more than once. Use `event_id` where present, otherwise the record's `id`, `transaction_id` or `deposit_id` with its `status`.
- **Don't rely on order.** `deposit.created` can arrive after `deposit.updated`. Use `status` and timestamps.
- **Ignore unknown events.** New types are added over time.
- **Keep your secret safe**, and rotate it with `regenerate-secret` if it may have leaked.
- **Use HTTPS.**
