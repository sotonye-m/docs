The Yativo sandbox lets you develop and test your integration without moving real funds. Your account and each customer still have to pass verification before payment calls succeed. See [Sandbox KYC](/yativo-fiat/sandbox-kyc).

---

## Sandbox Base URL

```
https://smtp.yativo.com/api/v1
```

All other endpoints remain the same — just swap the base URL.

---

## Getting Started

You use the **same Yativo account** for both sandbox and production. Switch between environments by changing the base URL and the API key in your requests.

1. **Sign up** at [app.yativo.com](https://app.yativo.com) (if you haven't already)
2. **Create a sandbox API key** — in your sandbox dashboard, go to **Developers → API Keys**. Sandbox and production keys are separate.
3. **Call the sandbox base URL** with your sandbox key:

```bash
curl 'https://smtp.yativo.com/api/v1/ip-whitelist/check' \
  -H 'X-Api-Key: YOUR_SANDBOX_API_KEY' \
  -H 'X-Api-Secret: YOUR_SANDBOX_API_SECRET'
```

## Sandbox Behavior

| Feature | Sandbox | Production |
|---------|---------|------------|
| Payments | Simulated — no real funds | Real money moves |
| Your account | Approved only when `kyc_status` is `approved` and `is_kyc_submitted` is true. The sandbox dashboard collects this in a form. | The production dashboard opens a hosted verification page |
| Customer KYC | Same submission and hosted pages as production. Creating a customer does not approve them | Same submission and hosted pages |
| Virtual accounts | Issued after the customer is approved | Live bank accounts |
| Corporate cards | Available now. Employee KYC is approved on submission. See [Corporate Cards in Sandbox](/yativo-fiat/sandbox-corporate-cards) | Coming soon |
| Exchange rates | Live rates returned | Live rates |
| Webhooks | Fired normally | Fired normally |
| API logs | Recorded | Recorded |

## How to Test

<Steps>
  <Step title="Use the sandbox base URL">
    Set `https://smtp.yativo.com/api/v1` as your base URL in all requests.
  </Step>
  <Step title="Authenticate">
    Create a separate API key in your sandbox dashboard. Sandbox and production keys aren't interchangeable.
  </Step>
  <Step title="Verify your sandbox account">
    Complete business verification in the sandbox dashboard. Most API calls return 403 until `kyc_status` is `approved` and `is_kyc_submitted` is true. See [Sandbox KYC](/yativo-fiat/sandbox-kyc).
  </Step>
  <Step title="Create test customers">
    Use `POST /customer` to create customers. That call does not approve the customer. Submit KYC or KYB on `https://kyc.yativo.com`, the same way you do in production.
  </Step>
  <Step title="Create virtual accounts">
    After the customer is approved (`is_va_approved` is true), call `POST /business/virtual-account/create`.
  </Step>
  <Step title="Simulate deposits">
    Use the sandbox dashboard or API to trigger test deposits to your virtual accounts.
  </Step>
  <Step title="Test payouts">
    Call `POST /sendmoney` or `POST /wallet/payout` — payments are simulated and will transition through statuses.
  </Step>
</Steps>

## Example: Full Sandbox Test Flow

```javascript Node.js
const BASE = 'https://smtp.yativo.com/api/v1';

// 1. Authenticate with your sandbox API key
const headers = {
  'X-Api-Key': process.env.YATIVO_API_KEY,
  'X-Api-Secret': process.env.YATIVO_API_SECRET,
  'Content-Type': 'application/json',
  'Idempotency-Key': crypto.randomUUID(),
};

// 2. Your account has to be approved before customer and payment calls succeed.
const { data: profile } = await fetch(`${BASE}/profile`, { headers }).then(r => r.json());
console.log(profile.kyc_status, profile.is_kyc_submitted);

// 3. Create a customer. This does not approve KYC.
const { data: customer } = await fetch(`${BASE}/customer`, {
  method: 'POST', headers,
  body: JSON.stringify({
    customer_name: 'Test User',
    customer_email: 'test@example.com',
    customer_phone: '+5511999999999',
    customer_country: 'BRA',
    customer_type: 'individual',
  }),
}).then(r => r.json());

console.log('Customer:', customer.customer_id);
// Submit KYC at https://kyc.yativo.com/individual/{customer_id}
// Create a virtual account only after GET /customer/kyc/{customer_id}
// returns status "approved" and is_va_approved true.
```

## Differences from Production

- **Account and customer KYC are separate** — [Sandbox KYC](/yativo-fiat/sandbox-kyc) covers both. Creating a customer does not set them to approved
- **No real funds** — wallet balances may be pre-funded in sandbox; payouts simulate the full transaction lifecycle
- **Some payment methods may be limited** — not all live corridors are available in sandbox; contact your integration team if you need a specific one
- **Webhooks fire normally** — you'll receive all webhook events in sandbox; make sure your test endpoint is reachable

## Switching to Production

When you're ready to go live:

1. Change your base URL from `https://smtp.yativo.com/api/v1` to `https://api.yativo.com/api/v1`
2. Ensure your business KYC is approved in the dashboard
3. Customers complete KYC on `https://kyc.yativo.com`, the same way they do in sandbox
4. Update your webhook URL to point to your production endpoint

<Note>
  Sandbox and production have separate API keys. Change both the base URL and the API key when you go live.
</Note>
