---
title: "Virtual Accounts"
description: "Issue local virtual accounts to collect payments in multiple currencies"
---

Virtual accounts give each customer a unique local bank account number. When a payment arrives at that number, it is automatically matched and credited to the right customer — no manual reconciliation needed.

<Note>
  Each customer can hold **one virtual account per currency**. The customer needs an approved endorsement for that currency before you can issue the account. See [KYC Requirement](#kyc-requirement).
</Note>

## Supported Rails

Call `GET /business/virtual-account/currencies-and-endorsements` for the live list enabled on your account.

| Currency | Required endorsement | Rail / settlement | Region |
|----------|----------------------|-------------------|--------|
| `EURBASE` | `base` | SEPA | Europe |
| `USDBASE` | `base` | ACH / Wire | United States |
| `BRL` | `brazil` | PIX | Brazil |
| `MXN` | None (`null`) | SPEI | Mexico |
| `MXNBASE` | `spei` | SPEI | Mexico |
| `USDLATAM` | `brazil` | USD Latin America | Latin America |
| `USD` | `faster_payments` | ACH / Wire | United States |
| `EUR` | `faster_payments` | SEPA | Europe |
| `GBP` | `faster_payments` | Faster Payments / BACS | United Kingdom |
| `MXNUSD` | `faster_payments` | SPEI (settles in USD) | Mexico |
| `COPUSD` | `faster_payments` | Bre-B (settles in USD) | Colombia |
| `USDCOBO` | `cobo_pobo` | COBO / POBO | USD |
| `GBPCOBO` | `cobo_pobo` | COBO / POBO | GBP |
| `SGDCOBO` | `cobo_pobo` | COBO / POBO | SGD |
| `EURCOBO` | `cobo_pobo` | COBO / POBO | EUR |
| `CADCOBO` | `cobo_pobo` | COBO / POBO | CAD |
| `AUDCOBO` | `cobo_pobo` | COBO / POBO | AUD |
| `DKKCOBO` | `cobo_pobo` | COBO / POBO | DKK |
| `AEDCOBO` | `cobo_pobo` | COBO / POBO | AED |
| `NGNCOBO` | `cobo_pobo` | COBO / POBO | NGN |
| `PHPCOBO` | `cobo_pobo` | COBO / POBO | PHP |
| `NGN` | `naira` | Local transfer | Nigeria |
| `NGNBASE` | `native` | Local transfer (individuals and businesses) | Nigeria |

<Note>
  Nigerian naira accounts: use `NGNBASE` (requires an approved `native` endorsement — see [NGNBASE (`native`) endorsement requirements](/yativo-fiat/kyc#ngnbase-native-endorsement-requirements)) or `NGN` (requires an approved `naira` endorsement). Get the codes your account can issue from `GET /business/virtual-account/currencies-and-endorsements`.
</Note>

## Create Virtual Account

```
POST /business/virtual-account/create
```

<ParamField body="customer_id" type="string" required>
  The ID of the KYC-approved customer to issue the account to.
</ParamField>

<ParamField body="currency" type="string" required>
  Currency for the virtual account (see supported values above).
</ParamField>

<RequestExample>
```bash Brazil (PIX)
curl -X POST 'https://api.yativo.com/api/v1/business/virtual-account/create' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: unique-key-here' \
  -d '{
    "customer_id": "11111111-2222-4333-8444-555555555555",
    "currency": "BRL"
  }'
```

```bash Mexico (SPEI)
curl -X POST 'https://api.yativo.com/api/v1/business/virtual-account/create' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: unique-key-here' \
  -d '{
    "customer_id": "11111111-2222-4333-8444-555555555555",
    "currency": "MXNBASE"
  }'
```

```javascript Node.js
const { data } = await client.post('/business/virtual-account/create', {
  customer_id: customerId,
  currency: 'BRL',
}, {
  headers: { 'Idempotency-Key': crypto.randomUUID() },
});
console.log('Account number:', data.data.account_number);
```
</RequestExample>

<ResponseExample>
```json Success
{
  "status": "success",
  "status_code": 201,
  "message": "Virtual account creation in progress",
  "data": {
    "account_id": "va_xxxxxx",
    "account_number": "9900123456",
    "account_type": "savings",
    "currency": "BRL",
    "customer_id": "11111111-2222-4333-8444-555555555555",
    "created_at": "2026-04-01T10:00:00Z"
  }
}
```
</ResponseExample>

## Delete Virtual Account

```
DELETE /business/virtual-account/delete-virtual-account/{id}
```

<ParamField path="id" type="string" required>
  The virtual account ID to delete.
</ParamField>

<RequestExample>
```bash cURL
curl -X DELETE 'https://api.yativo.com/api/v1/business/virtual-account/delete-virtual-account/va_xxxxxx' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET'
```
</RequestExample>

The account stops accepting funds and you receive a [`virtual_account.deleted`](/yativo-fiat/webhooks#virtual_accountdeleted) webhook. An ID that doesn't exist or isn't yours returns `404`.

## Bulk Account Creation

Create virtual accounts for multiple customers in a single request. Useful when onboarding a batch of pre-verified customers.

```
POST https://api.yativo.com/api/v1/business/virtual-account/bulk-account-creation
```

<Note>
  Requires `Idempotency-Key` header. Every customer needs an approved endorsement for the currency before bulk creation.
</Note>

<ParamField body="accounts" type="array" required>
  Array of account creation objects.

  <Expandable title="accounts item fields">
    <ParamField body="customer_id" type="string" required>
      The KYC-approved customer UUID.
    </ParamField>
    <ParamField body="currency" type="string" required>
      Currency for the virtual account (e.g. `"BRL"`, `"MXNBASE"`, `"USDBASE"`).
    </ParamField>
  </Expandable>
</ParamField>

<RequestExample>
```bash cURL
curl -X POST 'https://api.yativo.com/api/v1/business/virtual-account/bulk-account-creation' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: bulk-va-june-001' \
  -d '{
    "accounts": [
      { "customer_id": "11111111-2222-4333-8444-555555555555", "currency": "BRL" },
      { "customer_id": "11111111-2222-4333-8444-555555555555", "currency": "BRL" },
      { "customer_id": "f7e8d9c0-1a2b-3c4d-5e6f-7a8b9c0d1e2f", "currency": "MXNBASE" }
    ]
  }'
```
</RequestExample>

## Enable / Disable Virtual Account

Suspend or reactivate a virtual account without deleting it. Suspended accounts stop receiving deposits.

```
PUT https://api.yativo.com/api/v1/business/virtual-account/enable_disable_virtual_account
```

<ParamField body="account_id" type="string" required>
  The virtual account ID.
</ParamField>

<ParamField body="action" type="string" required>
  `"enable"` or `"disable"`.
</ParamField>

<RequestExample>
```bash Disable
curl -X PUT 'https://api.yativo.com/api/v1/business/virtual-account/enable_disable_virtual_account' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: disable-va-001' \
  -d '{
    "account_id": "va_xxxxxx",
    "action": "disable"
  }'
```

```bash Re-enable
curl -X PUT 'https://api.yativo.com/api/v1/business/virtual-account/enable_disable_virtual_account' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: enable-va-001' \
  -d '{
    "account_id": "va_xxxxxx",
    "action": "enable"
  }'
```
</RequestExample>

## Refund a Payin

Reverse a specific incoming deposit back to the sender. Use this when a customer payment needs to be returned.

```
POST https://api.yativo.com/api/v1/business/virtual-account/refundPayin/{externalId}
```

<ParamField path="externalId" type="string" required>
  The external transaction ID of the deposit to refund. This is returned in the `virtual_account.deposit` webhook payload.
</ParamField>

<Note>
  Requires `Idempotency-Key` header. Refunds are subject to the availability of the underlying payment rail — not all currencies support reversals.
</Note>

<RequestExample>
```bash cURL
curl -X POST 'https://api.yativo.com/api/v1/business/virtual-account/refundPayin/TXNMP2HK81BHJ' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: refund-TXNMP2HK81BHJ-001'
```
</RequestExample>

## KYC Requirement

Each currency needs a specific endorsement. Find it with:

```bash
curl -X GET 'https://api.yativo.com/api/v1/business/virtual-account/currencies-and-endorsements' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET'
```

Then check that the customer's endorsement for it is `approved`, either from the `endorsement.updated` webhook or from the `endorsement` list on `GET /customer/{customer_id}`. If it isn't, submit or fix KYC first. See [Track verification with endorsements](/yativo-fiat/kyc#track-verification-with-endorsements).
