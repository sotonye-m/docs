---
title: "Beneficiaries"
description: "Save recipients' account details once and reuse them for every payout"
---

A beneficiary is a recipient's saved account details for one payout method, such as a bank account, CLABE or PIX key. Add it once and reference its `id` in every payout, with no need to re-enter account details.

<Accordion title="Type Definitions">
```typescript
interface Beneficiary {
  id: string;                         // use as beneficiary_payment_method_id / payment_method_id
  gateway_id: number;                 // payout method ID
  currency: string;
  nickname: string;
  payment_data: Record<string, unknown>;
  created_at: string;
}

interface PayoutMethod {
  id: number;
  method_name: string;
  country: string;
  currency: string;
  base_currency: string;
}
```
</Accordion>

## Supported payout countries


## Payout methods by country

Returns available payment rails and their integer IDs for a destination country. The `id` from this response is used as `payment_method_id` in subsequent steps.

```
GET /payment-methods/payout?country={iso3}
```

<ParamField query="country" type="string" required>
  Destination country in ISO 3166-1 alpha-3 format (e.g. `CHL`, `MEX`, `BRA`).
</ParamField>

<RequestExample>
```bash Mexico
curl -X GET 'https://api.yativo.com/api/v1/payment-methods/payout?country=MEX' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET'
```
</RequestExample>

<ResponseExample>
```json Success (Mexico)
{
  "status": "success",
  "data": [
    {
      "id": 30,
      "method_name": "SPEI",
      "country": "MEX",
      "currency": "MXN",
      "base_currency": "MXN"
    }
  ]
}
```
</ResponseExample>

## Payment method form fields

Retrieve the exact bank detail fields required for a payment method before saving them.

```
GET /beneficiary/form/show/{payment_method_id}
```

<ParamField path="payment_method_id" type="number" required>
  The integer payment method ID from the `/payment-methods/payout` response.
</ParamField>

<RequestExample>
```bash SPEI (Mexico, id=30)
curl -X GET 'https://api.yativo.com/api/v1/beneficiary/form/show/30' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET'
```
</RequestExample>

## Add beneficiary

Save the recipient's account details. Use the form fields returned above to know exactly which keys are required.

```
POST /beneficiaries/payment-methods
```

<ParamField body="gateway_id" type="integer" required>
  The payout method ID from `/payment-methods/payout`.
</ParamField>

<ParamField body="payment_data" type="object" required>
  The recipient's account details, using the fields from `GET /beneficiary/form/show/{{id}}` (e.g. `account_number`, `bank_code`, `clabe`, `pix_key`).
</ParamField>

<ParamField body="currency" type="string" required>
  Currency of the payout method, e.g. `CLP`, `MXN`, `BRL`.
</ParamField>

<ParamField body="nickname" type="string" required>
  A label you'll recognise the beneficiary by.
</ParamField>

<ParamField body="customer_id" type="string">
  The customer the account belongs to. Some USD bank account methods require it. When they do and it's missing, the request returns a validation error naming it.
</ParamField>

<RequestExample>
```bash Chile (CLP bank transfer)
curl -X POST 'https://api.yativo.com/api/v1/beneficiaries/payment-methods' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: unique-key-here' \
  -d '{
    "gateway_id": 21,
    "currency": "CLP",
    "nickname": "Carlos Mendez - Banco de Chile",
    "payment_data": {
      "account_number": "12345678",
      "bank_code": "001",
      "account_type": "checking"
    }
  }'
```

### Ecuador (USD)

- Find the method with `GET /payment-methods/payout?country=ECU&currency=USD`. Bank codes are listed in its form (`GET /beneficiary/form/show/{payment_method_id}`).
- `document_type` is `IDCD` (cédula), `CCPT` (passport) or `TXID` (RUC). `account_type` is `checking` or `savings`.
- Payouts are 1.00 to 10,000.00 USD and can include cents.
- The payout also names the sender: the customer the payout is for, or your business when there's no customer.
- These transfers are completed manually, so they can take longer. They stay `processing` until the bank transfer is confirmed.
