---
title: "KYC / KYB Verification"
description: "Verify individual customers (KYC) and business customers (KYB) to unlock virtual accounts and payment rails"
---

Yativo requires identity verification before customers can access payment services such as virtual accounts, send money, and payment rails. Individual users go through **KYC** (Know Your Customer) and businesses go through **KYB** (Know Your Business).

## Environments

| Environment | Base URL |
|---|---|
| Production API | `https://api.yativo.com/api/v1` |
| Sandbox API | `https://smtp.yativo.com/api/v1` |
| KYC Platform | `https://kyc.yativo.com` |

<Note>
  KYC and KYB submissions are sent to **`https://kyc.yativo.com`**, not the main API base URL. All other endpoints (status check, update) use the standard base URL. Send your `X-Api-Key` and `X-Api-Secret` headers on every request. Sandbox uses this same KYC platform. See [Sandbox KYC](/yativo-fiat/sandbox-kyc).
</Note>

---

## Integration approaches

| Approach | Best for | Effort |
|---|---|---|
| **Hosted KYC/KYB link** | Quick integration, iframe embed | Low |
| **API submission** | Programmatic flow, native UI | High |

**Hosted URLs:**
- Individual: `https://kyc.yativo.com/individual/{customer_id}`
- Business: `https://kyc.yativo.com/business/{customer_id}`

## Verification flow

<Steps>
  <Step title="Create a customer">
    Call `POST /customer` to create a customer record and receive a `customer_id`.
  </Step>
  <Step title="Upload documents (if using API)">
    Use `POST /storage/upload` to upload files and receive back a hosted URL. Pass those URLs in the KYC payload. Alternatively, embed files as base64-encoded strings.
  </Step>
  <Step title="Submit KYC or KYB">
    POST to `https://kyc.yativo.com/api/individual-kyc/submit` or `https://kyc.yativo.com/api/business-kyc/submit`.
  </Step>
  <Step title="Poll or receive webhook">
    Check `GET /customer/kyc/{customer_id}`, or listen for the `customer.updated` and `endorsement.updated` [webhook events](/yativo-fiat/webhooks).
  </Step>
  <Step title="Customer approved">
    When `status` is `"approved"` and `is_va_approved` is `true`, service endorsements are activated and payment rails become available.
  </Step>
</Steps>

## Upload documents

Before submitting KYC, upload any document files you will reference.

Every file must be PDF, JPG, JPEG, PNG, HEIC or TIF, and between **5 KB and 30 MB**. ID document images (`image_front_file`, `image_back_file`, `uploaded_documents[*].file`) on individual KYC accept PDF, JPG, JPEG and PNG only. Each file field accepts a hosted URL, a base64 data URI (`data:image/jpeg;base64,...`) or a `multipart/form-data` upload. Every file is virus-scanned.

```
POST /storage/upload
```

Send the file as `multipart/form-data` with the field name `document`.

<RequestExample>
```bash cURL
curl -X POST 'https://api.yativo.com/api/v1/storage/upload' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -F 'document=@/path/to/passport_front.jpg'
```
</RequestExample>

<ResponseExample>
```json Success
{
  "status": "success",
  "status_code": 200,
  "message": "Request successful",
  "data": {
    "document": "https://storage.yativo.com/documents/abc123/passport_front.jpg"
  }
}
```
</ResponseExample>

Use the returned `document` value in the `selfie_image`, `image_front_file`, `proof_of_address_file`, and similar fields below.

## Individual KYC

### Submit

```
POST https://kyc.yativo.com/api/individual-kyc/submit
```

This is a five-step data model submitted in one payload. All required fields must be present in a single request.

A successful response means the submission passed validation and was accepted. It doesn't mean the customer is approved. Verification runs afterwards, so treat the customer as pending until [their status](#check-kyc--kyb-status) changes.

#### Step 1 — Personal details

| Field | Type | Required | Notes |
|---|---|---|---|
| `customer_id` | string | ✓ | UUID from `POST /customer` |
| `first_name` | string | ✓ | Max 1024 chars |
| `last_name` | string | ✓ | Max 1024 chars |
| `middle_name` | string | | Optional |
| `email` | string | ✓ | Valid email address |
| `calling_code` | string | ✓ | Dial code, e.g. `"+1"`, `"+234"`. Must match `^\+\d{1,4}$` |
| `phone` | string | ✓ | Digits only, 8–15 characters |
| `birth_date` | string | ✓ | `YYYY-MM-DD`. The customer must be at least 18 |
| `nationality` | string | ✓ | ISO 3166-1 alpha-2, e.g. `"US"`, `"NG"`, `"BR"` |
| `gender` | string | ✓ | `"male"` or `"female"` |
| `taxId` | string | ✓ | Tax identification number. Letters and digits only, up to 255 characters. `"123-45-6789"` is rejected; send `"123456789"` |
| `selfie_image` | file | ✓ | Selfie photo. PDF/JPG/JPEG/PNG/HEIC/TIF, 5 KB–30 MB |
| `bvn` | string | NG only | 11-digit Bank Verification Number. Required when `nationality` or `residential_address.country` is `"NG"` |
| `nin` | string | NG only | 11-digit National ID Number. Required when `nationality` or `residential_address.country` is `"NG"` |
| `usd_virtual_account`, `eur_virtual_account`, `gbp_virtual_account`, `native_endorsement` | boolean | | Services to verify the customer for. See [Virtual account flags](#virtual-account-flags) |

#### Step 2 — Residential address

| Field | Type | Required | Notes |
|---|---|---|---|
| `residential_address.street_line_1` | string | ✓ | Max 256 chars |
| `residential_address.street_line_2` | string | | Optional |
| `residential_address.city` | string | ✓ | Max 256 chars |
| `residential_address.state` | string | ✓ | Subdivision code, e.g. `"CA"`. `"US-CA"` is also accepted |
| `residential_address.postal_code` | string | ✓ | Max 256 chars. Use `GET /postal-codes/{countryCode}` to check the format |
| `residential_address.country` | string | ✓ | ISO 3166-1 alpha-2 |
| `residential_address.proof_of_address_file` | file | ✓ | Utility bill, bank statement, etc. PDF/JPG/JPEG/PNG/HEIC/TIF |

#### Step 3 — Identifying information

At least one government-issued ID document is required.

| Field | Type | Required | Notes |
|---|---|---|---|
| `identifying_information[*].type` | string | ✓ | See [ID types by country](#id-types-by-country) |
| `identifying_information[*].issuing_country` | string | ✓ | ISO 3166-1 alpha-2 |
| `identifying_information[*].number` | string | ✓ | Document number |
| `identifying_information[*].date_issued` | string | ✓ | `YYYY-MM-DD`, must be before today |
| `identifying_information[*].expiration_date` | string | ✓ | `YYYY-MM-DD`, must be after today |
| `identifying_information[*].image_front_file` | file | ✓ | PDF/JPG/JPEG/PNG |
| `identifying_information[*].image_back_file` | file | | Required for cards with a back side |

#### Step 4 — Risk and purpose

| Field | Type | Required | Notes |
|---|---|---|---|
| `employment_status` | string | ✓ | See [enum values](#employment_status) |
| `most_recent_occupation_code` | string | ✓ | Code from `GET /auth/occupation-codes`. Must be a listed code |
| `expected_monthly_payments_usd` | string | ✓ | See [enum values](#expected_monthly_payments_usd) |
| `source_of_funds` | string | ✓ | See [enum values](#source_of_funds) |
| `account_purpose` | string | ✓ | See [enum values](#account_purpose) |
| `account_purpose_other` | string | If `account_purpose` is `"other"` | Description of the purpose |
| `acting_as_intermediary` | boolean | | Whether the customer acts as intermediary for third parties |
| `annual_salary` | string | | Up to 20 characters |
| `current_employer` | string | | Up to 512 characters |
| `immigration_status` | string | | `"Permanent U.S. Resident"`, `"Non-Permanent U.S. Resident"` or `"Non-Resident of U.S."` |

The API accepts unknown values for `employment_status`, `expected_monthly_payments_usd`, `source_of_funds` and `account_purpose`, but verification fails later if they aren't on the lists below. The `201` response lists them under `warnings`, along with other values verification is likely to reject. Check `warnings` and fix those fields with a [partial update](#partial-update-on-the-kyc-platform). Use the lookup endpoints in [Reference lookups](#reference-lookups).

#### Step 5 — Supporting documents

| Field | Type | Required | Notes |
|---|---|---|---|
| `uploaded_documents[*].type` | string | ✓ | Document type identifier |
| `uploaded_documents[*].file` | file | ✓ | PDF/JPG/JPEG/PNG |

#### Virtual account flags

| Flag | Rule |
|---|---|
| `usd_virtual_account`, `eur_virtual_account` | Verify the customer for USD or EUR virtual accounts |
| `gbp_virtual_account` | Can be combined with any other flag. May add a KYC fee |
| `native_endorsement` | Can be combined with any other flag |
| `eurde_virtual_account` | Not available to customers created on or after 2 September 2026. When `true`, `usd_virtual_account` and `eur_virtual_account` must be `false` |

If the same person is already verified under another of your customers, the submission is refused. Use the existing customer instead.

## Business KYB

### Submit

```
POST https://kyc.yativo.com/api/business-kyc/submit
```

#### Step 1 — Business basics

| Field | Type | Required | Notes |
|---|---|---|---|
| `customer_id` | string | ✓ | UUID from `POST /customer` (must be `customer_type: "business"`) |
| `business_legal_name` | string | ✓ | Official registered legal name, max 255 chars |
| `business_trade_name` | string | ✓ | Trade / DBA name, max 255 chars |
| `business_description` | string | ✓ | What the business does, 140–5000 chars |
| `email` | string | ✓ | Business contact email |
| `business_type` | string | ✓ | `cooperative`, `corporation`, `llc`, `partnership`, `sole_prop`, `trust`, or `other` |
| `registration_number` | string | ✓ | Government registration / incorporation number, max 100 chars |
| `incorporation_date` | string | ✓ | `YYYY-MM-DD`, must be before today |
| `tax_id` | string | If no `identifying_information` | Business tax ID. Letters and digits only, up to 255 characters |
| `incorporation_country` | string | | ISO 3166-1 alpha-2 |
| `phone_calling_code` | string | | Must match `^\+[1-9]\d{0,3}$` |
| `phone_number` | string | | Digits only, 7–15 characters |
| `business_industry` | string | | Industry category |
| `primary_website` | string | ✓ | Full URL |
| `is_dao` | boolean | | Whether the business is a DAO |
| `statement_descriptor` | string | | How the name appears on statements, max 22 chars |

#### Step 2 — Addresses

Both `registered_address` and `physical_address` use the same structure:

| Field | Type | Required | Notes |
|---|---|---|---|
| `street_line_1` | string | ✓ | Max 255 chars |
| `street_line_2` | string | | Optional |
| `city` | string | ✓ | Max 100 chars |
| `state` | string | ✓ | Subdivision code from `GET /business-kyc/subdivisions/{countryCode}`, e.g. `"CA"`. `"US-CA"` is also accepted |
| `postal_code` | string | ✓ | Must match the country's format. See `GET /postal-codes/{countryCode}` |
| `country` | string | ✓ | ISO 3166-1 alpha-2 |
| `proof_of_address_file` | file | ✓ | Required for both addresses |

#### Step 3 — Associated persons

At least one person is required. Include all UBOs, directors, and authorized signers.

People who own less than the ownership threshold are dropped from the submission, and the response tells you who was dropped. The threshold is `ownership_threshold` (5–100, default 25). At least one person must meet it. The combined `ownership_percentage` of everyone with `has_ownership: true` can't exceed 100.

| Field | Type | Required | Notes |
|---|---|---|---|
| `first_name` | string | ✓ | Max 100 chars |
| `last_name` | string | ✓ | Max 100 chars |
| `birth_date` | string | ✓ | `YYYY-MM-DD`. The person must be at least 18 |
| `nationality` | string | ✓ | ISO 3166-1 alpha-2 |
| `email` | string | ✓ | Personal email |
| `phone` | string | | Digits only, 7–15 characters |
| `tax_id` | string | | Personal tax ID. Letters and digits only, up to 255 characters |
| `annual_salary` | string | | Up to 20 characters |
| `title` | string | | E.g. `"CEO"`, `"Director"` |
| `ownership_percentage` | number | ✓ | 0–100 |
| `relationship_established_at` | string | | `YYYY-MM-DD`, must not be in the future |
| `residential_address` | object | ✓ | Same structure as Step 2, including `proof_of_address_file` |
| `identifying_information` | array | ✓ | See below |
| `has_ownership` | boolean | | Has ownership stake |
| `has_control` | boolean | | Has operational control |
| `is_signer` | boolean | | Authorized signer |
| `is_director` | boolean | | Director |

Each person's `identifying_information` needs at least one ID that isn't a tax ID, such as a passport or national ID. Associated persons use `image_front` and `image_back`, not the `_file` names used in individual KYC:

| Field | Required | Notes |
|---|---|---|
| `type` | ✓ | ID type, e.g. `passport`, `national_id`, `drivers_license` or `tax_id` |
| `number` | ✓ | For `tax_id`, letters and digits only |
| `issuing_country` | | ISO 3166-1 alpha-2 |
| `expiration` | | `YYYY-MM-DD`, after today |
| `image_front` | ✓ | File |
| `image_back` | Except `passport` and `tax_id` | File |

#### Step 4 — Risk and purpose

| Field | Type | Required | Notes |
|---|---|---|---|
| `account_purpose` | string | ✓ | Business values only. See [KYB enum values](#kyb-account_purpose) |
| `account_purpose_other` | string | If `account_purpose` is `"other"` | |
| `source_of_funds` | string | ✓ | Business values only. See [KYB enum values](#kyb-source_of_funds) |
| `high_risk_activities` | array | ✓ | See [enum values](#high_risk_activities-kyb). Use `["none_of_the_above"]` if none apply |
| `high_risk_activities_explanation` | string | If any high-risk activities listed | |
| `conducts_money_services` | boolean | | |
| `conducts_money_services_description` | string | If `conducts_money_services` is `true` | |
| `compliance_screening_explanation` | string | If `conducts_money_services` is `true` | |
| `estimated_annual_revenue_usd` | string | | |
| `expected_monthly_payments_usd` | integer | ✓ | Expected monthly volume in USD, at least 1 |
| `operates_in_prohibited_countries` | string | | `"yes"` or `"no"` |
| `ownership_threshold` | integer | | Ownership threshold for associated persons, 5–100. Default 25 |
| `has_material_intermediary_ownership` | boolean | | |

#### Step 5 — Regulated activity

| Field | Type | Notes |
|---|---|---|
| `pep_status` | boolean | **Required.** Whether any associated person is a politically exposed person |
| `third_party_msb_payments` | boolean | **Required.** Whether the business makes payments for third-party money services businesses |
| `regulated_activity.regulated_activities_description` | string | Optional |
| `regulated_activity.primary_regulatory_authority_country` | string | ISO 3166-1 alpha-2 |
| `regulated_activity.primary_regulatory_authority_name` | string | |
| `regulated_activity.license_number` | string | |

#### Step 6 — Business documents

At least one document is required.

| Field | Type | Required | Notes |
|---|---|---|---|
| `documents[*].purpose` | string | ✓ | `business_registration`, `proof_of_address`, `tax_documents`, `compliance_documents`, `financial_statements`, `certificate_of_good_standing`, `portfolio_statement` or `board_minutes` |
| `documents[*].description` | string | ✓ | Human-readable description |
| `documents[*].file` | file | ✓ | File attachment |

#### Step 7 — Business identifying information (optional)

Business-level ID documents (e.g. business licence).

| Field | Type | Notes |
|---|---|---|
| `identifying_information[*].type` | string | |
| `identifying_information[*].issuing_country` | string | ISO 3166-1 alpha-2 |
| `identifying_information[*].number` | string | |
| `identifying_information[*].description` | string | |
| `identifying_information[*].expiration` | string | `YYYY-MM-DD`, after today |
| `identifying_information[*].image_front` | file | Required when `type` is `tax_id` |
| `identifying_information[*].image_back` | file | |

#### Step 8 — Extra documents

`extra_documents` is an array of `{ "type": "...", "file": ... }`. These are required:

| `type` | When |
|---|---|
| `shareholding_structure` | Always. A chart of the business's ownership |
| `board_resolution` | When an associated person has `is_signer: true` and `is_director: false` |

#### Optional business profile

You can also send these top-level fields to describe the business's activity. All are optional.

| Field | Notes |
|---|---|
| `industry_vertical`, `meeting_mode`, `primary_account_purpose` | Strings, up to 255 characters |
| `obo_usage` | `"yes"` or `"no"`: whether the business moves money on behalf of others |
| `monthly_volume_usd`, `avg_transaction_usd`, `max_transaction_usd` | Numbers. `avg_transaction_usd` can't exceed `max_transaction_usd` |
| `sender_geographies` | Any of `Africa`, `Europe`, `North America`, `South America`, `Asia` |
| `sender_industries` | Any of `E-commerce`, `Wholesale`, `Retail`, `Logistics`, `Manufacturing`, `Consulting`, `Others` |
| `sender_types` | `individuals`, `businesses` or `both` |
| `top_5_senders`, `top_5_beneficiaries` | Up to 5 names each |
| `collection_currencies` | Three-letter currency codes from `GET /transaction-currencies` |
| `beneficiary_geographies` | Two-letter country codes from `GET /transaction-countries` |
| `beneficiary_types` | `individual`, `business` or `both` |
| `primary_payout_method` | `ach`, `wire`, `sepa`, `swift`, `local_transfer`, `mobile_money` or `crypto` |

KYB also accepts the [virtual account flags](#virtual-account-flags).

### Resubmit one endorsement

After a customer updates their ID document or selfie, re-run verification for one endorsement without touching the others:

```
POST https://api.yativo.com/api/v1/customer/kyc/resubmit/{customer_id}/{endorsement}
```

`endorsement` is one of `base`, `sepa`, `spei`, `faster_payments`, `naira`, `virtual_card`, `asian` or `brazil`. This works for individual customers only.

```bash cURL
curl -X POST 'https://api.yativo.com/api/v1/customer/kyc/resubmit/c586066b-0f29-468f-b775-15483871a202/faster_payments' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Idempotency-Key: resubmit-fp-001'
```

```json Success
{
  "status": "success",
  "status_code": 200,
  "message": "Request successful",
  "data": { "message": "KYC resubmission for \"faster_payments\" queued." }
}
```

A `200` means the resubmission was queued, not that verification finished. Check the endorsement's `status` with `GET /customer/{customer_id}`. Its `metadata.last_resubmission` shows whether the resubmission itself could be processed:

| `last_resubmission.message` when `success` is `false` | Meaning |
|---|---|
| `Identity document and selfie are required before resubmission.` | Upload both, then retry |
| `Verification has not been started for this customer yet.` | The customer must complete initial verification for this endorsement first |
| `Submission failed.` | A temporary error. Safe to retry |

| Status | `data.error` | Cause |
|---|---|---|
| `404` | `Customer not found` | No customer with that ID on your account |
| `404` | `Individual KYC submission not found` | The customer has no KYC data yet |
| `422` | `This endpoint only supports individual customers` | The customer is a business |
| `422` | `Unknown endorsement "...". Valid endorsements: ...` | `endorsement` isn't supported |

`service` in the customer's `endorsement` list is title-cased, for example `"Faster payments"`. Compare it with the lowercase form you sent.

## Error handling

The KYC platform returns validation errors in its own shape, with `422`:

```json
{
  "success": false,
  "message": "Validation error.",
  "validation_errors": {
    "residential_address.postal_code": ["The residential address postal code field is required."]
  },
  "field_labels": {
    "residential_address.postal_code": "Residential address › Postal code"
  },
  "field_hints": {
    "residential_address.postal_code": "Call GET /postal-codes/{countryCode} for the expected format."
  }
}
```

`validation_errors` lists every failing field. `field_labels` gives a readable name for each, and `field_hints` gives advice where available. Show both next to the matching form field. KYB returns `"message": "Validation failed."` and may add notices about [associated persons below the ownership threshold](#business-kyb).

### Common errors and fixes

| Error | Fix |
|---|---|
| `customer_id does not exist` | Create the customer first with `POST /customer` |
| `nationality must be 2 characters` | Use ISO 3166-1 alpha-2 (e.g. `"US"`, `"NG"`) |
| `birth_date` must be a date before or equal to 18 years ago | The person must be at least 18 |
| `Tax ID must contain only letters and digits, up to 255 characters.` | Remove dashes, spaces and dots |
| File must not be smaller than 5 KB or greater than 30 MB | Resize the file |
| `Business with the provided Customer_ID not found.` (`404`) | Create the customer first with `POST /customer` |
| `Upload a shareholding structure chart.` | Add an `extra_documents` entry with `type: "shareholding_structure"` |
| `At least one non-tax-ID identifying document (e.g. passport, national ID) is required.` | Add a passport or national ID for that associated person |
| `expiration_date must be a date after today` | ID document must not be expired |
| `bvn is required` | Required for Nigerian nationals and residents. Exactly 11 digits |
| `nin is required` | Required for Nigerian nationals and residents. Exactly 11 digits |
| `calling_code is invalid` | Must be `+` followed by 1–4 digits, e.g. `"+1"`, `"+234"` |
| `identifying_information is required` | At least one ID document must be included |
| `documents is required` | KYB requires at least one business document |

## Implementation notes

- KYC review typically completes within **24 hours**. Complex cases may take longer.
- Use `Idempotency-Key` on all POST and PUT requests to prevent duplicate submissions.
- Files can be passed as hosted URLs (from `POST /storage/upload`) or base64-encoded strings — both are accepted.
- For Nigerian nationals or residents (`nationality` or `residential_address.country` is `"NG"`), `bvn` and `nin` are mandatory regardless of which ID type is provided.
- `state` accepts `"US-CA"` and `"CA"`. Send the bare code from the subdivisions lookup.
- Use the `PATCH` endpoints in [Update a KYC submission](#update-a-kyc-submission) for small corrections instead of resubmitting everything.
