---
title: "Customers"
description: "Create and manage wallet customers for your end users"
---

The Customers API lets you create managed accounts for your own customers. Each customer gets their own wallets and transaction history under your platform account — you keep full programmatic control while each customer's data stays separate.

This is the foundation of a wallet-as-a-service product: you use the Yativo API on your backend, and your customers use your interface.

<Note>
  **These are wallet customers — not card customers.** If you are issuing crypto cards, your cardholders are managed separately via the [Card Issuer API](/api-reference/issuer/customers). The two use different customer records and endpoints.
</Note>

<Accordion title="Type Definitions">
```typescript
interface Customer {
  _id: string;            // The customer ID used in every other customer endpoint
  username: string;
  email: string;
  phone_number: string;
  user_id: string;        // Your platform account
  createdAt: string;
  updatedAt: string;
}

interface CustomerListItem extends Customer {
  wallet_address: string | null;   // First wallet address, if any
  balance_usd: number;             // Total wallet balance in USD
}

interface CustomerDetails {
  customer: Customer;
  assets: CustomerWallet[];
  balance_usd: number;
  wallet_address: string | null;
  metrics: {
    total_volume: number;       // USD
    total_sent: number;         // USD
    total_received: number;     // USD
    first_active: string;
    last_active: string | null;
    transaction_count: number;
  };
}
```
</Accordion>

## Create a customer

```
POST /v1/customers/create-customer
```

<ParamField body="username" type="string" required>
  Display name for the customer.
</ParamField>

<ParamField body="email" type="string" required>
  Customer email address. Must be unique.
</ParamField>

```bash
curl -X POST 'https://crypto-api.yativo.com/api/v1/customers/create-customer' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "username": "Acme Corp",
    "email": "billing@acme.com"
  }'
```

```json Response
{
  "status": true,
  "message": "Customer created successfully !",
  "data": {
    "_id": "6650a1f2c3d4e5f6a7b8c9d0",
    "username": "Acme Corp",
    "email": "billing@acme.com",
    "phone_number": "",
    "user_id": "664f0e1d2c3b4a5968778695",
    "createdAt": "2026-09-30T10:00:00.000Z",
    "updatedAt": "2026-09-30T10:00:00.000Z"
  }
}
```

A `customer.created` webhook is sent when the customer is created.

## Update a customer

```
PATCH /v1/customers/{customer_id}
```

Send only the fields you want to change.

<ParamField body="username" type="string">Display name.</ParamField>
<ParamField body="email" type="string">Email address.</ParamField>
<ParamField body="phone_number" type="string">Phone number.</ParamField>

```bash
curl -X PATCH 'https://crypto-api.yativo.com/api/v1/customers/6650a1f2c3d4e5f6a7b8c9d0' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{ "phone_number": "+14155550100" }'
```


## Customer wallets

Add wallets to a customer with the Assets API:

```bash
# Add a wallet for a customer
curl -X POST 'https://crypto-api.yativo.com/api/v1/assets/add-customer-asset' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "customer_id": "6650a1f2c3d4e5f6a7b8c9d0",
    "ticker_name": "USDC_SOL"
  }'

# List a customer's wallets
curl -X POST 'https://crypto-api.yativo.com/api/v1/assets/get-customer-assets' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{ "customer_id": "6650a1f2c3d4e5f6a7b8c9d0" }'
```

| Field | Required | Notes |
|---|---|---|
| `customer_id` | Yes | The customer ID. |
| `ticker_name` or `asset_id` | Yes | The asset to create a wallet for, e.g. `USDC_SOL`. |
| `allow_multiple` | No | By default, adding the same asset again returns the existing wallet. Set `true` to create another. |

## Auto-forward a customer's deposits

Forward incoming deposits on a customer's wallet to another address automatically, for example to sweep funds into your treasury.

### Set the rule

```
POST /v1/customers/{customer_id}/auto-forward
```

<ParamField body="destination_address" type="string" required>Address to forward to.</ParamField>
<ParamField body="asset_id" type="string" required>The asset to forward.</ParamField>
<ParamField body="chain" type="string" required>The chain, e.g. `SOL`.</ParamField>
<ParamField body="percentage" type="number" default="100">Share of each deposit to forward.</ParamField>
<ParamField body="minimum_amount" type="string" default="0.0001">Deposits below this aren't forwarded.</ParamField>
<ParamField body="enabled" type="boolean" default="true">Turn the rule on or off.</ParamField>

```bash
curl -X POST 'https://crypto-api.yativo.com/api/v1/customers/6650a1f2c3d4e5f6a7b8c9d0/auto-forward' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "destination_address": "7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZRuJosgAsU",
    "asset_id": "665a0b1c2d3e4f5a6b7c8d9e",
    "chain": "SOL",
    "percentage": 100
  }'
```

Calling it again for the same customer, asset and chain updates the existing rule.

### Get the rule

```
GET /v1/customers/{customer_id}/auto-forward
```

Returns the rule, or `null` if the customer has none. For rules across many wallets, see [Auto-Forwarding](/yativo-crypto/auto-forwarding).
