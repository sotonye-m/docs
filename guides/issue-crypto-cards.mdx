---
title: "Issue Crypto Cards"
description: "Step-by-step guide to issue a virtual card on your own account — from onboarding through card creation and funding"
---

This guide walks through the **own-account** card flow, where you issue a virtual card directly on your Yativo account (not through the B2B Card Issuer Program). Use this if you want a card for your own use. For programmatic customer card issuance see [B2B Card Issuer Program](/guides/b2b-card-issuer).

---

## 1. Start Onboarding

Register your card account:

```bash
POST /v1/yativo-card/onboard
Content-Type: application/json

{
  "email": "you@example.com"
}
```

```json Response
{
  "yativo_card_id": "yativo_card_abc123_1769031332068",
  "email": "you@example.com",
  "flow_status": "otp_requested",
  "next_step": "verify_otp"
}
```

An OTP is sent to your email.

---

## 2. Verify Email OTP

```bash
POST /v1/yativo-card/{yativoCardId}/verify-otp
Content-Type: application/json

{
  "otp": "847291"
}
```

```json Response
{
  "flow_status": "otp_verified",
  "next_step": "kyc_link"
}
```

---

## 3. Complete KYC

### Get KYC Link

```bash
GET /v1/yativo-card/{yativoCardId}/kyc-link
```

```json Response
{
  "kyc_url": "https://kyc.yativo.com/verify?token=...",
  "instructions": "Open this URL to upload your government ID and complete liveness check"
}
```

Open the `kyc_url` and complete the identity verification flow.

### Poll KYC Status

```bash
GET /v1/yativo-card/{yativoCardId}/kyc-status
```

Wait for `kyc_status: "approved"` before continuing. Card terms are automatically accepted when KYC is first approved.

---

## 4. Complete Source of Funds

### Get Questions

```bash
GET /v1/yativo-card/{yativoCardId}/source-of-funds
```

### Submit Answers

```bash
POST /v1/yativo-card/{yativoCardId}/source-of-funds
Content-Type: application/json

{
  "answers": [
    {"question": "EMPLOYMENT_STATUS", "answer": "EMPLOYED"},
    {"question": "SOURCE_OF_INCOME", "answer": "SALARY"}
  ]
}
```

---

## 5. Verify Phone Number

### Request OTP

```bash
POST /v1/yativo-card/{yativoCardId}/phone/request-verification
Content-Type: application/json

{
  "phoneNumber": "+14155552671"
}
```

### Verify OTP

```bash
POST /v1/yativo-card/{yativoCardId}/phone/verify
Content-Type: application/json

{
  "code": "382910"
}
```

---

## 6. Deploy Card Wallet

For own-account card holders, wallet deployment is a manual step:

### Initiate Deployment

```bash
POST /v1/yativo-card/{yativoCardId}/safe/deploy
```

### Poll Until Ready

```bash
GET /v1/yativo-card/{yativoCardId}/safe/deploy
```

```json Deployed
{
  "deployed": true,
  "wallet_address": "0xABCD...",
  "network": "ethereum"
}
```

Wait for `deployed: true` before creating a card.

<Note>
  B2B customers managed through the Card Issuer Program have their wallets provisioned
  automatically after KYC approval — no manual step required.
</Note>

---

## 7. Create Virtual Card

```bash
POST /v1/yativo-card/{yativoCardId}/cards/virtual
```

```json Response
{
  "card_id": "b2dc97ab-03f9-49eb-c72f-95be13815278",
  "card_type": "virtual",
  "status": "active",
  "activated_at": "2026-04-01T12:30:00.000Z",
  "funding_wallet": {
    "address": "SoLFundingWalletAddressXXX",
    "network": "solana",
    "asset": "USDC"
  }
}
```

Use [Get Card View Token](/api-reference/cards/ephemeral-token) to securely display the full card number and CVV.

---

## 8. Fund Your Card

Get your card wallet deposit address:

```bash
GET /v1/yativo-card/{yativoCardId}/wallet/funding-address
```

```json Response
{
  "address": "SoLFundingWalletAddressXXX",
  "network": "solana",
  "asset": "USDC",
  "minimum_deposit": 1.00
}
```

Send USDC to this address. Funds are automatically converted and applied to your card balance.

---

## 9. Manage Your Card

### Freeze / Unfreeze

```bash
POST /v1/yativo-card/{yativoCardId}/cards/{cardId}/freeze
POST /v1/yativo-card/{yativoCardId}/cards/{cardId}/unfreeze
```

### View Transactions

```bash
GET /v1/yativo-card/{yativoCardId}/transactions
```

### File a Dispute

```bash
# Get reason codes first
GET /v1/yativo-card/{yativoCardId}/transactions/dispute-reasons

# File dispute
POST /v1/yativo-card/{yativoCardId}/transactions/{transactionId}/dispute
Content-Type: application/json

{
  "reason_code": "NOT_AS_DESCRIBED"
}
```

## Flow Summary

```
onboard → verify OTP → KYC → source of funds → phone verify → deploy wallet → create card → fund
```
