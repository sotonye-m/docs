As a card issuer you can withdraw funds from any customer's card balance directly back to your master wallet. The withdrawal is initiated with a single API call — Yativo handles the signing and submission to the card network automatically. The funds go through a short processing window before settling in your master wallet.

<Note>
  Withdrawals are available to **master wallet** programs only. The destination is always your program's master wallet for the matching currency — the same wallet you use to fund customer cards.
</Note>

---

## How It Works

```
POST /v1/card-issuer/withdraw-from-card
         │
         ▼
  Card balance debited (processing)
         │
         ├── card.withdrawal.initiated  ← fires immediately
         │
         ▼
  Funds clear through the card network (~3 minutes)
         │
         ├── card.withdrawal.settled    ← funds confirmed on card side
         ├── master_wallet.withdrawal   ← master wallet credited (companion)
         ├── master_wallet.deposit      ← balance credit + on-chain tx_hash
         ├── customer.balance.updated   ← card balance snapshot updated
         └── card.withdrawal.failed     ← cleared; no funds moved
```

You receive a `card.withdrawal.initiated` webhook the moment the withdrawal is accepted. Once the card network confirms settlement (~3 minutes), three events fire together: `card.withdrawal.settled`, `master_wallet.withdrawal`, and `master_wallet.deposit`. The `master_wallet.deposit` event carries the authoritative on-chain `tx_hash` and includes `withdrawal_id` for correlation.

## Identify the Card

Use **any** of these identifiers in the `id` field:

| Identifier | When to use |
|---|---|
| `yativo_card_id` | Most precise — always unique per card. **Recommended.** |
| `external_customer_id` | Your own reference ID set at onboarding |
| `customer_id` (ObjectId) | Yativo's internal customer document ID |
| `email` | Convenient, but only works when the customer has **exactly one** card |

<Warning>
  **Email with multiple cards:** If the email resolves to more than one card, the request returns a `422 MULTIPLE_CARDS` error. Use `GET /v1/card-issuer/customers` to list all cards and their `yativo_card_id`s, then retry with a specific `yativo_card_id`.
</Warning>

## Initiate a Withdrawal

```bash
POST /v1/card-issuer/withdraw-from-card
Authorization: Bearer YOUR_TOKEN
Content-Type: application/json
```

```json Request
{
  "id": "yc_a1b2c3d4e5f6",
  "amount": 50
}
```

**Request fields**

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | string | ✓ | Card identifier — see table above |
| `amount` | number | ✓ | Amount to withdraw in the card's currency (e.g. `50` = $50.00 USD) |

---

### Success Response

```json
{
  "success": true,
  "data": {
    "withdrawal_id": "cwd_1748012345678_x7k2qp",
    "yativo_card_id": "yc_a1b2c3d4e5f6",
    "amount": 50.0,
    "amount_minor": 5000,
    "currency": "USD",
    "status": "initiated",
    "message": "Withdrawal initiated. Funds will arrive in your master wallet shortly.",
    "estimated_settlement_at": "2026-05-23T14:35:00.000Z"
  }
}
```

Store `withdrawal_id` — you will receive it back in every subsequent webhook event for this withdrawal, making it easy to correlate.

---

### Error Responses

**Email with multiple cards**
```json
{
  "success": false,
  "error": "MULTIPLE_CARDS",
  "message": "This email is linked to multiple cards. Use yativo_card_id to specify which card to withdraw from.",
  "hint": "Call GET /api/card-issuer/customers to list all cards and their yativo_card_ids."
}
```

**Insufficient balance**
```json
{
  "success": false,
  "error": "INSUFFICIENT_BALANCE",
  "message": "Available balance (30.00 USD) is less than the requested amount (50.00 USD).",
  "available": 30.0,
  "available_minor": 3000,
  "currency": "USD"
}
```

**Card not found**
```json
{
  "success": false,
  "error": "CARD_NOT_FOUND",
  "message": "No active card found for the provided identifier."
}
```

## Webhook Events

Subscribe to these event types when registering your webhook:

| Event | When it fires |
|---|---|
| `card.withdrawal.initiated` | Withdrawal accepted and queued on the card network |
| `card.withdrawal.settled` | Funds cleared and confirmed on the card side |
| `card.withdrawal.failed` | Withdrawal rejected or failed; no funds moved |
| `master_wallet.withdrawal` | Companion to `settled` — confirms the master wallet credit |
| `master_wallet.deposit` | Master wallet balance credited; carries the on-chain `tx_hash` and `withdrawal_id` for correlation |
| `customer.balance.updated` | Card balance snapshot after the withdrawal settles |

---

### `card.withdrawal.initiated`

Fires immediately after the withdrawal is accepted. The card's available balance is reduced at this point.

```json
{
  "id": "evt_1748012320000_abc123",
  "type": "card.withdrawal.initiated",
  "created_at": "2026-05-23T14:32:00.000Z",
  "data": {
    "withdrawal_id": "cwd_1748012345678_x7k2qp",
    "yativo_card_id": "yc_a1b2c3d4e5f6",
    "amount": 50.0,
    "amount_minor": 5000,
    "currency": "USD",
    "status": "initiated",
    "estimated_settlement_at": "2026-05-23T14:35:00.000Z"
  }
}
```

---

### `card.withdrawal.settled`

Fires once the card network confirms the withdrawal. Funds are now in your master wallet.

```json
{
  "id": "evt_1748012512000_def456",
  "type": "card.withdrawal.settled",
  "created_at": "2026-05-23T14:35:12.000Z",
  "data": {
    "withdrawal_id": "cwd_1748012345678_x7k2qp",
    "yativo_card_id": "yc_a1b2c3d4e5f6",
    "amount": 50.0,
    "amount_minor": 5000,
    "currency": "USD",
    "tx_hash": "0xa8739436c44460738a4147055530e450f8b55694e2448875e72cd25eb29cd21f",
    "card_balance": 143.97,
    "card_balance_minor": 14397,
    "status": "settled",
    "settled_at": "2026-05-23T14:35:12.000Z"
  }
}
```

**Settled payload fields**

| Field | Type | Description |
|---|---|---|
| `withdrawal_id` | string | Matches the ID from the initiated event |
| `yativo_card_id` | string | The card the funds were withdrawn from |
| `amount` | float | Amount withdrawn |
| `amount_minor` | integer | Amount in minor units (cents) |
| `currency` | string | `USD`, `EUR`, or `GBP` |
| `tx_hash` | string | On-chain transaction hash of the settlement |
| `card_balance` | float \| absent | Card's remaining balance after the withdrawal. Present when the settlement notification arrives from the card network directly; absent when confirmed via the on-chain fallback path |
| `card_balance_minor` | integer \| absent | `card_balance` in minor units |
| `status` | string | Always `"settled"` |
| `settled_at` | ISO 8601 | Timestamp when settlement was confirmed |

---

### `master_wallet.deposit`

Also fires when the withdrawal settles — the returning funds credit your master wallet balance, which is reported as a deposit. This is the event that carries the confirmed on-chain `tx_hash`. It includes `withdrawal_id` and `yativo_card_id` so you can correlate it with the originating withdrawal.

<Note>
  You will receive **both** `master_wallet.withdrawal` and `master_wallet.deposit` for the same settlement. `master_wallet.withdrawal` is the semantic signal that a withdrawal completed. `master_wallet.deposit` is the balance-credit event and is the authoritative source for the on-chain transaction hash. Join them using `withdrawal_id`.
</Note>

```json
{
  "id": "evt_1748012512000_mno345",
  "type": "master_wallet.deposit",
  "created_at": "2026-05-23T14:35:12.000Z",
  "data": {
    "settlement_id": "6a294844e71b09a046f28103",
    "withdrawal_id": "cwd_1748012345678_x7k2qp",
    "yativo_card_id": "yc_a1b2c3d4e5f6",
    "deposit_amount": 50.0,
    "deposit_amount_minor": 5000,
    "wallet_balance": 550.0,
    "wallet_balance_minor": 55000,
    "currency": "USD",
    "tx_hash": "0xa8739436c44460738a4147055530e450f8b55694e2448875e72cd25eb29cd21f",
    "solana_tx_hash": null,
    "status": "settled"
  }
}
```

## Handling Events in Code

```typescript
async function handleWithdrawalEvent(event: CardIssuerEvent) {
  const { withdrawal_id, yativo_card_id, amount, currency } = event.data;

  switch (event.event) {
    case "card.withdrawal.initiated":
      // Mark the withdrawal as in-progress in your system
      await db.withdrawals.update(withdrawal_id, { status: "processing" });
      break;

    case "card.withdrawal.settled":
      // Withdrawal confirmed on the card side — update status
      await db.withdrawals.update(withdrawal_id, {
        status: "settled",
        tx_hash: event.data.tx_hash,
      });
      break;

    case "master_wallet.deposit":
      if (withdrawal_id) {
        // This deposit is the return credit from a withdrawal — record the tx_hash
        // and update the master wallet balance. withdrawal_id links back to the withdrawal.
        await db.withdrawals.update(withdrawal_id, { tx_hash: event.data.tx_hash });
        await db.masterWallet.credit(event.data.deposit_amount, currency);
      } else {
        // Regular master wallet deposit (not withdrawal-related)
        await db.masterWallet.credit(event.data.deposit_amount, currency);
      }
      break;

    case "card.withdrawal.failed":
      // No funds moved — alert your ops team if needed
      await db.withdrawals.update(withdrawal_id, {
        status: "failed",
        reason: event.data.reason,
      });
      break;
  }
}
```

## Amount Fields

Every webhook payload exposes the amount in two formats:

| Field | Format | Example |
|---|---|---|
| `amount` | Decimal float | `50.00` |
| `amount_minor` | Integer minor units (cents) | `5000` |

Use `amount_minor` for arithmetic to avoid floating-point rounding issues.

---

## Settlement Timing

Withdrawals are processed through the card network and typically settle within **a few minutes**. During this window:

- The card's available balance is reduced immediately
- The card may be temporarily restricted from new transactions
- If the withdrawal fails, the hold is released automatically and the balance is restored

Plan your UX so that you communicate the pending state clearly — `card.withdrawal.initiated` means "in progress", not "done". Only `card.withdrawal.settled` means the funds are available in your master wallet.

## Checking Status Directly

Webhooks are the primary way to track a withdrawal, but if you need to poll instead (or reconcile after a missed webhook), [Get Transfer Status](/api-reference/issuer/transfer-status) accepts a `withdrawal_id` the same way it accepts a funding `transfer_id`:

```bash
GET /v1/card-issuer/transfers/{withdrawal_id}
Authorization: Bearer YOUR_TOKEN
```

The response includes `type: "withdrawal"`, `status` (`initiated` | `processing` | `settled` | `failed`), and `tx_hash` once settled.

## Tips

- **Always use `yativo_card_id`** when customers have multiple cards. Email lookup is a convenience shortcut for single-card customers only.
- **Reconcile with `withdrawal_id`** — every event carries the same `withdrawal_id`, making it straightforward to match initiated → settled/failed without storing extra state.
- **Do not retry on `initiated`** — once a withdrawal is initiated, attempting the same amount again will create a second withdrawal. Wait for the `settled` or `failed` event before deciding to retry.
- **Check `master_wallet.balance.updated`** to confirm your master wallet balance is what you expect after the credit.
