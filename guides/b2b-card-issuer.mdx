The Yativo Card Issuer Program lets businesses issue Visa/Mastercard cards to their own customers under their brand. This guide covers setup, customer onboarding, card creation, and funding.

<Note>
  Important distinction: WaaS customer creation and card-customer onboarding are different flows. For card issuance in the Issuer Program, use `POST /api/v1/yativo-card/customers/onboard` (this guide), not the generic WaaS customer-create endpoints.
</Note>

<Note>
  The Issuer Program requires an invitation from Yativo. Contact your account manager or [support@yativo.com](mailto:support@yativo.com) to get started.
</Note>

## Who This Is For

- Fintech and neobank platforms
- Payroll and expense platforms
- Crypto exchanges offering spending cards
- Businesses issuing cards to end users

<Steps>

<Step title="Apply for issuer program">

```bash cURL
curl -X POST https://crypto-api.yativo.com/api/v1/card-issuer/apply \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "funding_structure": "master_wallet",
    "iban_enabled": false
  }'
```

Funding structures:

| Value | Network | Best for |
|---|---|---|
| `master_wallet` | Solana | Higher throughput funding model |
| `non_master` | XDC | Customer self-funding model |

</Step>

<Step title="Wait for approval">

```bash cURL
curl -X GET https://crypto-api.yativo.com/api/v1/card-issuer/status \
  -H "Authorization: Bearer <token>"
```

Continue once status is `approved`.

</Step>

<Step title="Onboard customer">

Create a customer-scoped card profile with email and one identifier.

Required:

- `email`
- one of `customer_id` or `external_customer_id`

```bash cURL
curl -X POST https://crypto-api.yativo.com/api/v1/yativo-card/customers/onboard \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "priya@yourapp.com",
    "external_customer_id": "your_user_id_8821"
  }'
```

Typical response:

```json
{
  "success": true,
  "data": {
    "yativo_card_id": "yativo_card_customer_123",
    "external_customer_id": "your_user_id_8821",
    "email_masked": "pr***@yourapp.com",
    "next_step": "verify_otp",
    "otp_expires_in_seconds": 600
  }
}
```

</Step>

<Step title="Complete onboarding and create card">

After onboard, run the customer lifecycle until eligible for card creation.

Core endpoints:

- `POST /api/v1/yativo-card/customers/:yativoCardId/verify-otp`
- `GET /api/v1/yativo-card/customers/:yativoCardId/kyc-link`
- `GET /api/v1/yativo-card/customers/:yativoCardId/kyc-status`
- `POST /api/v1/yativo-card/customers/:yativoCardId/source-of-funds`
- `POST /api/v1/yativo-card/customers/:yativoCardId/phone/request-verification`
- `POST /api/v1/yativo-card/customers/:yativoCardId/phone/verify`
- `POST /api/v1/yativo-card/customers/:yativoCardId/safe/deploy`

Then create the virtual card:

```bash cURL
curl -X POST "https://crypto-api.yativo.com/api/v1/yativo-card/customers/:yativoCardId/cards/virtual" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{}'
```

List cards for that customer:

```bash cURL
curl -X GET "https://crypto-api.yativo.com/api/v1/yativo-card/customers/:yativoCardId/cards" \
  -H "Authorization: Bearer <token>"
```

</Step>

<Step title="Fund customer card">

Use issuer funding endpoint.

Endpoint:

- `POST /api/v1/card-issuer/fund-customer`

Required fields:

- one identifier: `customer_id` or `card_id` or `external_id` or `email`
- `amount`
- `source_chain` (`SOL` or `XDC`)

Optional:

- `destination_token` (`USDC`, `EURe`, `GBPe`)
- `pricing_mode` (`send_x`, `receive_x`)

```bash cURL
curl -X POST "https://crypto-api.yativo.com/api/v1/card-issuer/fund-customer" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "your_user_id_8821",
    "amount": 100,
    "source_chain": "SOL",
    "destination_token": "EURe",
    "pricing_mode": "send_x"
  }'
```

Typical response:

```json
{
  "success": true,
  "data": {
    "bridge_id": "bridge_01HX9ABC",
    "status": "initiated",
    "source": {
      "chain": "SOL",
      "amount": 100,
      "wallet": "SoLMasterWalletAddress..."
    },
    "destination": {
      "chain": "GNO",
      "token": "EURe"
    },
    "pricing_mode": "send_x",
    "estimated_output": "99.10",
    "estimated_time": "2-10 minutes"
  }
}
```

</Step>

<Step title="Monitor via webhooks">

Relevant events:

</Step>

</Steps>

## Bulk Issuance Pattern

Batch customer onboard calls, complete onboarding steps, then create cards.

```typescript TypeScript
async function bulkIssueCards(users: UserRecord[]) {
  const BATCH_SIZE = 10;
  const DELAY_MS = 200;

  for (let i = 0; i < users.length; i += BATCH_SIZE) {
    const batch = users.slice(i, i + BATCH_SIZE);

    await Promise.all(batch.map(async (user) => {
      const onboard = await api.post("/yativo-card/customers/onboard", {
        email: user.email,
        external_customer_id: user.id,
      });

      const yativoCardId = onboard.data.data.yativo_card_id;

      // Complete OTP/KYC/phone/safe flow before creating card.
      const card = await api.post(`/yativo-card/customers/${yativoCardId}/cards/virtual`, {});

      await db.users.update(user.id, {
        yativoCardId,
        cardId: card.data.data.card_id,
      });
    }));

    if (i + BATCH_SIZE < users.length) {
      await new Promise((r) => setTimeout(r, DELAY_MS));
    }
  }
}
```
