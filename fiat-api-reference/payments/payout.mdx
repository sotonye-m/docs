---
title: "Initiate Payout"
description: "Send money from your wallet to a customer's saved payout method"
---

Send money from one of your wallets to a customer's saved payout method. Pass a `quote_id` to lock the rate and fees for 5 minutes, or send `amount` to pay at the current rate.

By default `amount` is what leaves your wallet. Set `amount_type` to `receive` to fix what the customer receives instead. See [Pay out by receive amount](/yativo-fiat/exchange-rates#pay-out-by-receive-amount).

```
POST /wallet/payout
```

<Note>
  Requires an `Idempotency-Key` header. Use a unique key per payout to prevent duplicate transactions.
</Note>

## Request body

<ParamField body="debit_wallet" type="string" required>
  The wallet currency to debit (e.g. `"USD"`, `"EUR"`).
</ParamField>

<ParamField body="payment_method_id" type="integer" required>
  The customer's saved payout method ID, from `POST /beneficiaries/payment-methods`.
</ParamField>

<ParamField body="customer_id" type="string" required>
  The customer the payout method belongs to.
</ParamField>

<ParamField body="quote_id" type="string">
  A payout quote from `POST /exchange-rate` (`method_type: "payout"`). Recommended. The quote supplies the amount, so `amount` and `amount_type` are ignored. The quote's `method_id` must be the payout method behind `payment_method_id`.
</ParamField>

<ParamField body="amount" type="number">
  Required if `quote_id` is not provided. With `amount_type: "send"` (the default), the amount to send in the `debit_wallet` currency. With `amount_type: "receive"`, the amount the customer receives in the payout currency.
</ParamField>

<ParamField body="amount_type" type="string" default="send">
  `send` or `receive`. Ignored when `quote_id` is provided. In both modes fees are added on top and charged to your wallet.
</ParamField>

<RequestExample>
```bash cURL — With quote (recommended)
curl -X POST 'https://api.yativo.com/api/v1/wallet/payout' \
  -H 'X-Api-Key: YOUR_API_KEY' \
  -H 'X-Api-Secret: YOUR_API_SECRET' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: payout-c586066b-2026-10-01-001' \
  -d '{
    "debit_wallet": "USD",
    "payment_method_id": 555,
    "customer_id": "da44a3e6-eb5d-429f-8d17-357aa5a6cdf2",
    "quote_id": "4a72ecf8-6c8a-4e38-9971-8aabe9f785ed"
  }'
```

## Response fields

| Field | Description |
|---|---|
| `transaction_id` | The transaction ID for this payout. Use it with `GET /transaction/tracking/{id}`. |
| `payout_id` | The payout ID. Use it with `GET /payout/fetch/{payout_id}`. |
| `status` | Starts as `pending`. Payouts settle asynchronously; use webhooks for the final status. |
| `amount_type` | `send` or `receive`, as applied to this payout. |
| `send_amount` | The amount sent, in the debit wallet currency, before fees. |
| `customer_receive_amount` | The amount the customer receives, in `currency`. |
| `debit_amount` | The total debited from your wallet, fees included. |
| `currency` | The payout currency. |
| `fees` | The full fee and rate breakdown. |

## Errors

| Status | `data.error` |
|---|---|
| `400` | `Insufficient wallet balance`. Nothing is debited. |
| `400` | `Quote has expired. Please generate a new quote.` |
| `400` | `Minimum withdrawal: ...` or `Maximum withdrawal: ...`. Limits are checked against the send amount and shown in your wallet currency, so a receive amount can be rejected for being above or below a limit. |
| `400` | `Unsupported withdrawal method for quotes`. The quote's method doesn't match the payout method. |
| `422` | `amount_type must be either send or receive` |
