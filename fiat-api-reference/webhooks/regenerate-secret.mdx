---
title: "Regenerate Webhook Secret"
description: "Issue a new signing secret for an existing webhook endpoint"
---

Regenerate the HMAC signing secret for a webhook. Use this after a secret is suspected to be compromised, or as part of a routine secret rotation policy.

```
POST https://api.yativo.com/api/v1/business/webhook/{webhook_id}/regenerate-secret
```

<Note>
  Requires `Idempotency-Key` header. After regeneration, update `YATIVO_WEBHOOK_SECRET` in your environment immediately — the old secret stops working right away.
</Note>

## Path parameters

<ParamField path="webhook_id" type="string" required>
  The ID of the webhook whose secret you want to regenerate.
</ParamField>

<RequestExample>
\`\`\`bash cURL
curl -X POST 'https://api.yativo.com/api/v1/business/webhook/wh-01abc123/regenerate-secret' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Idempotency-Key: regen-secret-001'
\`\`\`

\`\`\`javascript Node.js
const response = await fetch(
  \`https://api.yativo.com/api/v1/business/webhook/\${webhookId}/regenerate-secret\`,
  {
    method: 'POST',
    headers: {
      'Authorization': \`Bearer \${token}\`,
      'Idempotency-Key': \`regen-\${Date.now()}\`,
    },
  }
);
const data = await response.json();
// Update your environment with data.data.secret immediately
\`\`\`
</RequestExample>

<ResponseExample>
\`\`\`json Success
{
  "status": "success",
  "status_code": 200,
  "message": "Webhook secret regenerated successfully",
  "data": {
    "webhook_id": "wh-01abc123",
    "secret": "whsec_newb2c3d4e5f6...",
    "updated_at": "2026-06-01T10:00:00.000000Z"
  }
}
\`\`\`
</ResponseExample>

<Warning>
  The new secret is shown only once — store it securely immediately. The old secret is invalidated as soon as the new one is issued.
</Warning>
