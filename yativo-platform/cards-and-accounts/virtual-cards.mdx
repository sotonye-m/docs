This documentation covers:
- Virtual account listing
- Updating and expiring NGN virtual accounts
- Virtual account transaction history
- Transactions index
- Transaction details for payins (payment links) and payouts

All sample payloads below are anonymized for safe sharing.

## Environments

- Sandbox API: `https://smtp.yativo.com`
- Sandbox (alternate host): `https://smtp.yativo.com`
- Production API: `https://api.yativo.com`

On sandbox you can simulate an inbound deposit onto a virtual account (credits
the wallet and sends `virtual_account.deposit`) without waiting for a bank.
See [Testing on sandbox](/yativo-platform/testing/sandbox-testing).

## Authentication

All business endpoints need an authenticated request.

Server-to-server requests use your team's API key and secret:

```http
X-Api-Key: <YOUR_API_KEY>
X-Api-Secret: <YOUR_API_SECRET>
```

The Yativo dashboard sends the signed-in user's `Authorization: Bearer <ACCESS_TOKEN>`
instead. Since 15 October 2026, bearer tokens are only accepted from the
dashboard, and the legacy `POST /api/v1/auth/login` (`account_id` +
`app_secret`) flow is deprecated. Don't send a bearer token together with the
key pair. See [Authentication](/yativo-fiat/authentication).

## 1a) Update or Expire an NGN Virtual Account

These two endpoints only work on **NGN** virtual accounts. Any other currency
returns `422` (`Updating is not supported for this account` /
`Expiring is not supported for this account`).

### Update

```http
PUT /api/v1/business/virtual-account/update/{account_id}
Content-Type: application/json

{
  "account_name": "ANONYMIZED BUSINESS LTD",
  "expected_amount": 150000
}
```

| Field | Required | Notes |
|---|---|---|
| `account_name` | no | New name on the account, up to 100 characters. |
| `expected_amount` | no | Lock the account to accept only this exact NGN amount. Send `null` to remove the lock. |

Send at least one of the two fields, otherwise the request returns `422`.
The response is the updated virtual account record; the new values also
appear in `account_info` (`account_name`, `expected_amount`).

### Expire

```http
POST /api/v1/business/virtual-account/expire/{account_id}
```

Permanently stops the account from accepting funds. The account record and
its transaction history are kept, and its `status` becomes `expired`. This
can't be undone. Calling it on an account that is already expired returns
`200` with the message `Virtual account already expired`.

Deleting an NGN account with
`DELETE /api/v1/business/virtual-account/delete-virtual-account/{account_id}`
also expires it first.

A successful delete returns the deleted `account_id` and sends a
`virtual_account.deleted` webhook. An ID that doesn't exist or isn't yours
returns `404` (`Account with the provided ID does not exists`).

```json
{
  "status": "success",
  "status_code": 200,
  "message": "Request successful",
  "data": { "message": "Virtual account deleted successfully", "account_id": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d" }
}
```

| HTTP | `data.error` | Cause |
|---|---|---|
| 404 | `Invalid account ID supplied` | The account doesn't exist or isn't yours. |
| 422 | `... is not supported for this account` | The account isn't an NGN account. |
| 400 | `Unable to update virtual account, please try again later` / `Unable to expire virtual account, please try again later` | The change couldn't be applied. Retry later. |

## 2) Virtual Account Transaction History

### Endpoint

```http
POST /api/v1/business/virtual-account/history/{account_number}
```

### Important Crediting Notes

- `currency` + `amount`: value credited to the wallet.
- `amount_recevied` (API spelling): amount originally sent by sender.
- `sender_information`: payer account and identity details.
- `transaction_fee`: your own platform fee.
- If `amount_recevied` is greater than `amount`, the difference can come from rail/provider deductions (for example, FedWire fees) before settlement.

### Wallet Settlement Rules

- GBP virtual account (Faster Payments) settles into USD wallet.
- `MXNUSD` virtual account accepts MXN over SPEI and settles into USD wallet.
- `COPUSD` virtual account accepts COP over Bre-B and settles into USD wallet.
- EUR virtual account accepts EUR and settles in EUR only.
- NGN virtual account accepts NGN and settles in NGN.

For accounts that settle into USD, the deposit is converted at the prevailing
rate when it is credited. `amount_recevied` shows what the sender paid in the
local currency, and `amount` shows the USD credited.

## Notes for Integrators

- Keep `amount` and `amount_recevied` separate in your UI and reconciliation logic.
- Treat `amount` as wallet credit.
- Treat `amount_recevied` as sender-side transfer value.
- Show `transaction_fee` as your own platform fee.
- Rail/provider fee deductions (for example FedWire) can explain differences between sent and credited amounts.
